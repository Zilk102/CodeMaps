# Участие в разработке CodeMaps

[English](CONTRIBUTING.md) · [Русский](CONTRIBUTING.ru.md)

Спасибо за помощь! Исправление опечатки, новый язык, анализатор или MCP-инструмент: всё это приветствуется.

## С чего начать

1. Сделайте форк репозитория и склонируйте его.
2. Установите зависимости: `yarn install`. Проект использует **yarn**, `package-lock.json` не поддерживается. Нужен Node.js 22+.
3. Создайте ветку: `git checkout -b feature/короткое-имя` (или `fix/...`).
4. Запустите приложение: `npm run dev` (Vite + Electron).

Карта кодовой базы: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Перед пушем

Прогоните всё, что запускает CI, по возможности **в свежем клоне**:

```bash
npm run verify   # линт, формат, типы, тесты, сборки renderer и electron, проверки сложности/размера и дубликатов кода
```

Почему свежий клон: файлы вне git или в `.gitignore` (например, новый `src/types/*.d.ts`) и допущения, верные только для Windows, проходят у вас и падают на CI, который работает на Linux и Windows.

Полезные команды:

| Команда             | Что делает                                               |
| ------------------- | -------------------------------------------------------- |
| `npm run format`    | Prettier, запись                                         |
| `npm run lint:fix`  | ESLint с исправлениями                                   |
| `npm test`          | Vitest                                                   |
| `npm run mcp:smoke` | Вызывает каждый MCP-инструмент у запущенного CodeMaps    |
| `npm run docs:mcp`  | Пересоздаёт `docs/MCP_TOOLS.md` из описаний инструментов |

## Добавление MCP-инструмента

1. Зарегистрируйте его в `electron/mcp/register*.ts`.
2. Опишите в `electron/mcp/descriptors.ts` и отнесите к категории в `electron/mcp/docsGenerator.ts`.
3. Добавьте `mcpSettings.tools.<имя>` в `src/i18n/locales/{en,ru,zh}.json`.
4. Выполните `npm run docs:mcp`.
5. Ограничивайте ответ по размеру: используйте `okStatusToolResult` (он режет списки и общий объём) и добавьте `limit`, если инструмент возвращает список.

Каждый шаг проверяется тестами, пропуск уронит CI.

## Соглашения

- **Стиль**: Prettier и ESLint обязательны, TypeScript в строгом режиме.
- **Тесты**: добавляйте тест на изменяемое поведение; для бага пишите тест, который падает без исправления.
- **Коммиты**: [Conventional Commits](https://www.conventionalcommits.org/) (`feat:`, `fix:`, `docs:`, `chore:`), с описанием _что_ и _зачем_.
- **Упаковка**: воркер Kuzu работает под системным Node, поэтому каждый файл, который он загружает, должен подходить под `build.asarUnpack` в `package.json` (шаблоны различают регистр); это проверяет тест.

## Pull Request

1. Отправьте ветку в свой форк и откройте Pull Request в `main`.
2. Опишите, какую задачу он решает и как проверить; для интерфейса полезны скриншоты.
3. Дождитесь ревью. CI должен быть зелёным.

## Релизы (для мейнтейнеров)

Релизы запускаются git-тегами. Обновите `CHANGELOG.md` и `.github/release-body.md` (в нём должны быть секции на русском, английском и китайском), прогоните `npm run verify` в свежем клоне, запушьте `main`, затем создайте и запушьте тег: `git tag -a vX.Y.Z -m "release: vX.Y.Z" && git push origin vX.Y.Z`. Workflow Release берёт версию из тега, собирает артефакты для Windows и Linux и публикует их.

## Сообщения об ошибках

Создайте Issue с шагами воспроизведения, ожидаемым поведением, версиями ОС и Node.js и версией CodeMaps (её показывает MCP-сервер и она есть в имени файла релиза). По вопросам безопасности см. [SECURITY.md](SECURITY.md).
